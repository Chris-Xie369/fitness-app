# 一键打卡 设计文档（2026-09-30）

## 背景与需求

今天页（打卡首页）目前唯一的打卡路径：点「记录今天的训练」→ 跳转记录页 → 填动作+组数 → 保存。没有"点一下就算打卡"的轻量入口。

用户需求：首页支持点击打卡。已确认决策（方案 A）：

- 主按钮变为「一键打卡」，点击即完成打卡（周目标环 +1），无需当场填明细
- 「记录今天的训练」降为次按钮；打卡后当天随时可补记明细（走现有同日追加机制）
- 纯一键打卡，不带类型标签（力量/有氧等）；用户场景未提出，YAGNI

## 数据语义（核心决策）

**纯打卡 = 一条 `exercises: []` 的空训练记录（Workout）**，复用现有存储、备份、同日合并逻辑：

- **不新增任何存储字段**——不触发"types/load/parseBackup 三处同步"规则；备份导出/导入/导入前快照自动兼容
- 计数口径：按"该日期存在记录"即计入训练日（周目标环、连续天数、统计页训练日、周目标达成庆祝全部自动成立，它们只看日期不看动作数）；组数/容量/时长按 0/无计
- 同日补明细 = 现有追加机制：`normalizeWorkouts` 按日期合并 flatMap 动作，空数组天然兼容
- 纯打卡不写 `durationSec` / `updatedAt`（与类型注释语义一致）

### 必须修复的隐患

`App.tsx removeExercise` 的过滤 `.filter((w) => w.exercises.length > 0)` 会把纯打卡记录误删——对任何动作执行删除时，所有 0 动作的 workout 都会被清掉。改为只删除"本次刚被删空"的目标那条：`.filter((w) => w.id !== workoutId || w.exercises.length > 0)`。

## UI 设计

### 今天页（TodayTab）

- 未打卡：
  - 主按钮「**一键打卡**」（clay 实心 CTA，全宽）→ App 层创建空记录，toast「打卡成功，开练！」，周目标达成照常弹庆祝
  - 次按钮「记录今天的训练」（描边）→ 原跳转记录页
- 已打卡（纯打卡）：今日摘要行显示「今天已打卡 · 明细未记录 · **补记 ›**」（补记跳转记录页）；按钮恢复为「再记一次」（clay）
- 已打卡（有明细）：摘要行与按钮维持现状
- toast 复用现有 `lastAdded` 分支：`count === 0 && !appended` 落入「打卡成功，开练！」分支，无需新文案

### 历史页（HistoryTab）

- 列表摘要行：纯打卡天不显示「0 个动作 · 0 组」，改为「纯打卡 · 记录于 HH:mm」
- 详情卡：无动作明细时卡体显示「这一天只打了卡，没有动作明细」（有备注则显示备注），「删除整天」按钮保留——即反悔/取消打卡入口

### App.tsx

- `checkInToday()`：复用 `addWorkout({ id: uid(), date: todayStr(), createdAt: Date.now(), exercises: [] })`——庆祝管线（成就/PR/周目标）自动复用，停留今天页
- `removeExercise` 过滤修复（见上）

## 边界与口径

- 纯打卡日：月历/周报格照常打点（训练日语义）；无时长；按组数统计的成就徽章不受影响（0 组）
- 不可对过去日期纯打卡（本次不做）；删除整天 = 取消打卡
- 纯打卡计入训练日，否则打卡无意义

## 明确不做

打卡类型标签、过去日补打卡、打卡加备注、打卡确认弹窗（一键即达，反悔走历史页删除）
