# 宏量营养素（蛋白质/碳水/脂肪）显示 设计

日期：2026-09-16
状态：已获用户批准

## 背景与目标

饮食记录目前只显示热量。升级：每条克数记录显示蛋白/碳水/脂肪估算，当日汇总并与目标对照。这是对早前"营养素只显示目标、不追踪"决策的升级（用户主动提出），但不改变录入流程：仍然只录食物+克数（或手填大卡），宏量由库数据推导，零额外录入负担。

### 已确认的产品决策

1. **显示粒度**：每条克数记录行内显示 P/C/F 估算（小字），当日热量卡下加"今日三大营养素合计"。
2. **数据范围**：81 种库内食物全部补齐每百克 P/C/F（《中国食物成分表》/USDA 近似，与热量同口径：肉鱼虾熟重、主食熟重、冲调谷物干重、蔬果可食部）；库外手填大卡与学习估算记录**不显示宏量**（只有热量，无比例依据）。

## 架构

- 改 `src/lib/foods.ts`：`FoodItem` 扩展 `protein: number; carbs: number; fat: number`（每百克克数）；81 种全补。顺带修正一处口径遗留：鳕鱼 kcal 88（生值）→ 105（熟值，熟重口径统一；鳕鱼不在菜单 31 种内，菜单零变化约束不受影响）。
- 改 `src/lib/diet.ts`：
  - `macrosOf(name: string, grams: number): { p: number; c: number; f: number } | null` —— 用与 learnedKcal 相同的克数后缀正则拆出基础名，查库按克数换算，取整；拆不出克数或查不到返回 null
  - `dayMacros(meals: MealEntry[], date: string): { p: number; c: number; f: number }` —— 汇总当日所有 macrosOf 非 null 的记录
- 改 `src/tabs/DietTab.tsx` 记录视图：
  1. 记录列表每条克数记录：热量后小字 `P 31 · C 0 · F 5`（text-muted 弱化、tabular-nums）
  2. 「当日热量 vs 目标」卡底部一行：`今日 · 蛋白 95g · 碳水 210g · 脂肪 55g`；有 targetInfo 时各宏量后带目标范围对照（如 `蛋白 95g（120-145g）`，对照用 plan 视图同款 macroTargets 公式）
- MealEntry 结构、备份、统计均不变（纯展示层推导）。

## 边界

- 库外/学习估算记录：热量照旧，不显宏量；当日合计自动跳过它们
- 菜单「按菜单记录」写入的记录全是库内名，天然可估算
- 宏量为估算值，页脚已有"食材近似值"措辞，不另加声明

## 测试

- node 单测：81 种 P/C/F 值域断言（protein 0-40、carbs 0-75、fat 0-70，坚果类放宽 fat ≤65）；macrosOf（拆名/找不到/无克数）；dayMacros（混合记录汇总与跳过）
- mealplan 既有单测重跑（菜单热量仍零变化——31 种 kcal 不动，鳕鱼修正不在其中）
- 营养维度对抗审查核对 81 组数值合理性（项目惯例：数值内容过审查）
- 浏览器预览：记录鸡胸肉 150g → 行内 P 31 · C 0 · F 5，当日合计随之更新
